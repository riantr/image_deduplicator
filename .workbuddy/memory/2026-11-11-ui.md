# 2026-11-11：UI 完全重构

## 背景
前几轮优化了算法与性能，XAML 层始终未动过（记忆中标注「未经人工验证」）。
用户选择「完全重新设计」而非保守的样式调整。

## 改前的问题

原 `MainWindow.axaml` 956 行，其中约 600 行是 **11 个算法 Tab 页的重复代码**：

- 每个 Tab 页结构几乎一致（说明文字 + 3~5 个参数滑块 + 排序方式）
- 每新增一个参数就要改 11 处，极易遗漏
- 配色硬编码在每个 Style 里（`#2196F3`、`#4CAF50` 等散落各处）
- 边距/间距用魔法数字（`Padding="5"`、`Margin="2,0,0,0"`）
- ViewModel 里有 21 个命令，XAML 只用了 12 个 —— 9 个功能已实现但无入口

## 改后

### 1. 设计系统
- `App.axaml` 内联设计令牌（色板 / 字体层级 / 圆角）
- `Views/Controls.axaml` 集中定义所有控件样式
- 按钮按语义分变体：`accent` / `danger` / `ghost` / `subtle` / `large`

### 2. 算法设置：11 个 Tab 页 → 动态面板
一个下拉框 + 按算法动态显示字段，显示逻辑集中在
`Converters/AlgorithmConverters.cs` 的 11 个转换器中。

**关键权衡**：最初想用 `ConverterParameter="Sift,Surf"` 传算法集合，
但 XAML 属性里的嵌套双引号极其脆弱（试了 `&quot;` 转义、无引号等多种写法都失败）。
最终改为**每种参数一个预置转换器类**（`ShowHashSizeConverter` 等），
XAML 里只写 `Converter={StaticResource ShowHashSize}`，干净且不会出错。

### 3. 布局
- 顶部：品牌 + 三步流程指示 + 已载入数量
- 左侧：目录 / 算法 / 日志（滚动）+ 底部固定主操作
- 右侧：原图 ‖ 重复图 ‖ 重复项列表 + 底部操作栏
- 状态栏：进度与状态常驻

## UI 自动化测试（最有价值的产出）

新增 `Deduplicator.Tests/UiTests.cs`，用 **Avalonia Headless**
在无显示环境下构建完整控件树。

**为什么必须有**：`dotnet build` 通过 ≠ 能运行。
Avalonia 的资源解析、样式选择器、绑定都在运行时。
本轮靠这个测试抓出 **4 个编译期完全看不出的问题**：

1. `ResourceDictionary` 被 `StyleInclude` 引入 → 运行时 `InvalidCastException`
2. `Cursor="Default"` 不是合法值 → 启动即崩
3. 转换器返回 `Visibility` 枚举 —— **Avalonia 11 的 `IsVisible` 是 `bool`**
4. 遍历控件树时逻辑树与视觉树重复计数（Button 被数成 1344 个，实际 14 个）

断言数 103 → 117。

## Avalonia 11 的几个坑（血泪）

| 坑 | 说明 |
|---|---|
| `Visibility` 枚举不存在 | Avalonia 11 的 `IsVisible` 是 `bool`，照 WPF 习惯写会编译失败 |
| 无 `ResourceInclude` | 只能内联或用 `Application.Resources` 包裹 |
| `ResourceDictionary` 不能用 `StyleInclude` | 类型不匹配，运行时抛异常 |
| `Grid` 无 `ColumnSpacing` | Avalonia 11 不支持，只能靠 Margin |
| `Cursor="Default"` 非法 | 只能 `Hand` 等少数值 |
| `AppBuilder` 无 `Application` 属性 | 用 `Application.Current` |
| 遍历子控件 | `GetLogicalChildren` / `GetVisualChildren` 在 `LogicalExtensions` / `VisualExtensions`，需去重 |

## 未解决
- `--shot` 无头截图渲染出空白图（Avalonia Headless 的固有限制，
  Measure/Arrange 不触发完整绘制）。要截图需真实显示环境。

## 经验
1. **UI 重构必须配自动化测试**。XAML 的错误全在运行时，
   光靠编译通过来验证等于没验证。
2. **Avalonia ≠ WPF**。从 WPF 迁移过来最常见的错误就是
   `Visibility` 枚举、`ResourceDictionary` 用法、Grid 间距。
3. 遇到 API 不确定时，**写个小程序用反射查**比反复猜快得多
   （本轮查 `Visibility` 类型定义省了多次试错）。

## 追加：跑 `dotnet run` 时抓到启动即崩溃的 Bug

用户执行 `dotnet run` 后我实测，发现应用启动几秒即崩：

```
InvalidOperationException: Call from invalid thread
  at Avalonia.Threading.Dispatcher.VerifyAccess()
  at Avalonia.Controls.Button.get_Command()
  at RelayCommandBase.RaiseCanExecuteChanged()
  at AsyncRelayCommand.set_IsExecuting()
  at MainViewModel.SelectInputDirectory()
```

**根因**：`AsyncRelayCommand.ExecuteAsyncSafe` 用了 `ConfigureAwait(false)`，
导致 `await` 之后的代码脱离 UI 线程；`finally` 里复位 `IsExecuting` 时
在后台线程触发 `CanExecuteChanged`，该事件被 Avalonia 命令绑定用于读取
`Button.CanExecute` —— 跨线程访问控件属性，抛异常。

这是 UI 重构后才暴露的：重构前所有参数在 Tab 页里，
`SelectInputDirectory` 走的路径与现在不同。

**同类隐患**：`LoadImagesAsync` / `CalculateFeaturesAsync` /
`CompareFeaturesAsync` / `ExecuteDeduplicationAsync` 都有同样问题 ——
它们在 await 之后都会更新绑定到 UI 的属性。

**修复**：
1. `RaiseCanExecuteChanged` 先 `CheckAccess()`，否则 `Post` 到 UI 线程
2. 命令层去掉 `ConfigureAwait(false)`
3. ViewModel 层 5 处全部移除

**验证**：修复前启动数秒崩溃，修复后持续运行 25 秒无异常。

**教训**：UI 自动化测试验证的是「控件树能构建」，
但**运行时行为**（尤其是异步路径）只能真正跑起来才会暴露。
这次是靠用户实际执行 `dotnet run` 才发现的。

## 追加：按 Fluent Design 规范重构视觉体系

### 配色：从自造命名换成 WinUI 3 语义色

改前（自造，看不出设计意图）：
`SurfaceBrush` / `SurfaceAltBrush` / `TextPrimaryBrush` / `AccentBrush`

改后（Fluent 语义体系）：
`LayerFillColorDefaultBrush` / `SolidBackgroundFillColorBaseBrush` /
`TextFillColorPrimaryBrush` / `AccentFillColorDefaultBrush` …

**实际收益**：全部定义在 `ThemeDictionaries` 里，深色模式自动适配。
深色下强调色必须换（#005FB8 → #60CDFF），否则对比度不足。

### 尺寸：对齐规范刻度
- 圆角 4（控件）/ 8（卡片），控件高 32
- 卡片**不加阴影**，只用 1px 描边 + 圆角（Fluent 的 Layer 规范）
- 输入框聚焦时描边 1px → 2px 且转为强调色

### 补齐交互态
原样式缺 `:pressed` / `:disabled` / `:focus`，按钮点击和禁用态表现不一致。

### 测试
新增 `DesignTokenTests`：断言 19 个颜色令牌在**浅色 + 深色两套主题下都齐全**，
外加 2 个圆角与 5 级字阶。断言 119 → 128。

### 踩坑：TryFindResource 传 null 主题
`res.TryFindResource(key, null, out v)` 查不到 `ThemeDictionaries` 里的值，
19 个令牌全部报「缺失」，一度以为资源没定义成功。

修正：显式传 `ThemeVariant.Light` / `ThemeVariant.Dark`，
并注意需要 `(IResourceHost)Application.Current` 强转。

教训已写进测试代码注释。
