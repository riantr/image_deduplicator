# 2026-10-10 项目优化记录

## 背景
Avalonia + OpenCV 图片去重工具。发现两个致命问题：全分辨率图像常驻内存（OOM）、
O(n²) 暴力比对且单线程。全量做了内存/性能/重构/修Bug 四项优化。

## 核心改动

### 1. 内存：从「常驻全分辨率图像」改为「按需加载 + 紧凑特征」
- `ImageData` 删除 `Image` (全分辨率 Mat) 与 eager `BitmapImage` 字段，改为懒加载
- 新增 `Services/ThumbnailCache.cs`：有界 LRU + 单航班去重，内存与图片总数解耦
- `DeduplicationService.CalculateFeaturesAsync` 改为临时解码 → 算完即释放（`using`）
- `ImageHelper.LoadImage`（每图 PNG 重编码）拆为 `LoadMat`，Bitmap 改由缓存按需生成
- 效果：600 张 800×600 图特征常驻仅 ~1MB（原先单 Mat 就要 1.4MB/张）

### 2. 性能：预筛 + 并行 + 消除重复计算
- 新增 `Services/CandidatePrefilter.cs`
  - FileHash：文件大小分桶 → 哈希分桶（99.9% 削减）
  - A/D/PHash：分带 LSH（Multi-Probe），段数按阈值自适应保证无漏报
  - Histogram：通道峰值分桶（95%）
  - Lance：多表随机投影 LSH（92%）
  - 高碰撞保护：候选 ≥ 暴力 80% 时回退全量（汉明距离用 `BitOperations.PopCount` 极快）
- `CalculateFeaturesAsync` / `CompareFeaturesAsync` 改 `Parallel.For`，多核利用
- **消除原实现分组阶段的重复相似度计算**（原本工作量翻倍），改为复用缓存结果
- 进度上报改为每 25/100 次一报，避免 UI 调度风暴

### 3. 修 Bug（均为实测发现，非推测）
| 问题 | 影响 |
|---|---|
| `SIFT/ORB` 返回 `using` 管理的 Mat | **原生内存破坏 AccessViolationException**，必须 `Clone()` |
| `ComputeLanceVector` 取绝对值最大维 | 不同图 cosine=0.99998，**去重完全失效**。改为 PCA（`DimensionReducer.cs`） |
| `ExtractSegment` 分带未覆盖全部64位 | 10段×6位=60位，末4位永不索引 → 漏判。改为 `shift = i*64/segments` |
| `HammingDistance` 长度不符返回 64 | 硬编码，仅 hashSize=8 时凑巧正确。改为 `int.MaxValue` |
| `FileHash` 参数声明 MD5 实算 SHA256 | 改为 SHA256 并同步参数 |
| `new RelayCommand(async () => ...)` | 退化为 `async void`，异常被吞。改用 `AsyncRelayCommand` |
| `ExportLog` 用 `.Result` | UI 线程阻塞/死锁风险。改为 `async` |
| `GetTextureRichBlock` 每次 `new Random()` | 同一图每次结果不同。改为固定种子 |
| `ComputeSiftFeatures` 忽略 `maxFeatures` | 参数无效。已应用 |
| `ComputeLanceVector` HOG winSize 可能非法 | 小图抛异常。改为至少 16 且 8 的倍数 |

### 4. 结构与跨平台
- `MainViewModel` 1938 → 1246 行，改继承 `ViewModelBase`（消除重复 INotifyPropertyChanged）
- 新增 `Helpers/RelayCommand.cs`，抽出 `RelayCommandBase` 统一 RaiseCanExecuteChanged
- 新增 `Algorithms/DimensionReducer.cs`：对偶形式 PCA（Jacobi 特征分解），O(s³+s²d) 而非 O(d³)
- **跨平台修复**：原 csproj 只引用 `linux-x64` 运行时 + `LD_LIBRARY_PATH` + `.so` 软链接脚本，
  但用户在 Windows 开发。改为 NuGet 官方 runtime 包按平台条件引用，删除 `setup-opencv-libs.sh`
- 删除死代码 `FileHashService.cs`（已被内联实现取代）
- `LogService` 日志改为 150ms 批量提交 UI（原每条一次 Post）
- `ImageListWindow` 加载改为并行 + 批量 UI 提交（原逐项 Post）

## 验证
- 构建：0 错误 0 警告（优化前 8 警告）
- 端到端测试：23 项全通过（46 张图，11 种算法）
- 性能基准：360 张自然纹理图，FileHash 召回 60/60、预筛 99.9%；
  DHash 60/60、81.5%；Lance 92.2%；Histogram 95%

## 重要经验
1. **PHash/DHash 对纯色/低纹理图像区分度差**（cosine 可达 0.81），
   这是算法固有局限而非代码缺陷。纯色块基准图会让召回率看起来很差，不要误判。
2. OpenCvSharp 的 `Mat` 所有权必须明确：从 `using` 变量返回前必须 `Clone()`，
   否则调用方拿到悬垂指针 → AccessViolationException。
3. 返回 `using` 变量是**编译期无法发现**的错误，只能靠实测/代码审查发现。
